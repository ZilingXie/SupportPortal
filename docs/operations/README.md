## 维护方法

1. 环境、镜像或测试契约变化时，在同一 PR 更新对应说明及来源链接。维护者是该项改动的执行者与审阅者。
2. 每页保留核对日期；将来源所描述的配置与实时运行状态分开。历史方案只作为历史引用，不能直接当作当前操作入口。
3. 具体命令和完整配置清单优先留在已有 Runbook、脚本及配置文件中，避免复制后出现两套不同答案。
4. 只记录配置键名、用途和读取位置，不记录凭据、完整 DSN、Cookie 或客户工单内容。
5. 手工内容写在本目录，不写进 `.codesight/`。保持 CodeSight 默认输出到 `.codesight/`，不要把输出目录改成本目录。

现有规则要求代码改动完成后从根工作区 `main` 运行 `npx codesight --wiki`；它会重写自动生成的文章和索引。本目录不在该输出目录中，不受这次重建覆盖。纯文档改动按现有规则无需刷新代码地图。当前不依赖 Knowledge 模式、自动摘要或新增扫描任务。
