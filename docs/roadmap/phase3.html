02 / Runtime boundary

Phase 3 主链路

阶段目标不是让 AI 接管完整 case，而是把首次回复、人工处理和管理控制连接成一条可审计链路。

01Zendesk intake

客户开单后先通过 eligibility gate。

02AI first reply

只做首次有效回复与必要信息收集。

03Slack assignment

Round Robin 选定工程师并投递关联 case。

04Guarded handling

工程师回复经过 Guardrail，Admin 负责 reassign 与审计。

上线前技术依赖

Slack bot 权限、消息承载方式、thread/channel 可见性和 Zendesk 关联方式仍需验证。Roadmap 记录交付边界，不把未决的 Slack 方案写成既定实现。
