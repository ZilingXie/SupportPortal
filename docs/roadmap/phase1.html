SupportPortal Phase 1

从 Zendesk 平替，走向 AI-native Support System

这不是一次工具替换，而是把路由、质量检查、调查辅助和管理指标内建到 support 流程里。Phase 1 的目标是先证明系统可控、可审计、可小流量试运行。

  • 0:45 架构与角色变化
  • 1:35 Guardrail showcase
  • 2:25 Dashboard 与路线图
01 · Why now

传统 SaaS 已经很难承接我们的 support 目标。

Zendesk license 续费约 73k USD/year，但更大的问题不是价格，而是团队需要更深的流程、数据和质量控制能力。

SLA 回复不及时、升级等待和交接空档，都不能只靠事后报表管理。
73k 年费只买到通用 SaaS 能力，关键流程仍需要外部脚本、人工判断和临时补丁。
Billing 部分 invoice、account fraud / deactivate 等 case 不需要完整 HITL 流程，适合先做受控自动化 POC。
02 · Big picture

Phase 1 先不改变客户入口，只改变内部处理能力。

客户仍然从 Zendesk 进入；内部通过 Zendesk webhook / N8n 转到 SupportPortal，先跑 shadow mode、真实 case replay 和 1% 小流量门禁。

Zendesk / N8n保留现有客户入口，降低迁移风险。

Routing + Assignment识别 billing、technical、human review 与 SLA 风险。

03 · Role shift

AI 不是替代 support engineer，而是把 manager 的日常质量检查产品化。

客户侧体验暂时不变；工程师从重复流程中释放出来；AI agent 承担实时检查、辅助调查和跨系统协作。

Before

  • Manager 只能抽样 review，无法逐条检查技术细节、表达边界和 SLA 风险。
  • 客户不满通常要等客诉后才暴露，情绪和交接风险发现太晚。
  • 工程师反复 copy/paste 到外部 AI，过程不可审计、不可稳定复用。

After

  • 每次回复都先过 AI guardrail，低级错误在发送前被拦住。
  • 每条客户信息都可以做情感检测和 SLA 风险识别，提前报警。
  • AI agent 可以从研发 agent、日志 agent、数据 agent 汲取知识，逐步进入自主调查。
04 · Showcase

演示重点：AI 拒绝工程师的一次不完整回复。

这个 case 最能说明项目价值：AI 不急着替人回答，而是在客户看到之前拦住不完整、不安全、不可执行的回复。

Engineer draft
“We checked the account. Please try again later.”
  • 没有明确 conclusion：到底是什么问题？是否已处理？
  • 没有 proof：基于哪个系统、哪条 evidence、哪个时间点？
  • 没有 next step：客户下一步该做什么，谁负责跟进？
Rejected by AI Guardrail
  • 要求工程师补充可验证结论，避免模糊回答引发二次追问。
  • 提醒不要暴露内部证据或敏感信息，只输出 customer-safe 解释。
  • 如果信息不足，必须明确告诉客户下一步，而不是编造原因。
05 · Dashboard

管理指标也要从 SLA 时代升级到 AI guardrail 时代。

传统指标仍然重要，但 Phase 1 开始追踪 AI 是否真的降低风险、提升质量，并解释为什么某些 case 还不能自动化。

  • 传统指标：first response time、second response time、SLA risk、交互次数、一次回复解决率。
  • 新增指标：AI guardrail pass rate、approve / reject rate、not automated reason、route accuracy、response latency。
  • 下一步指标：客户情绪检测、negative feedback、reopen、自动化覆盖率和抽查通过率。
SLA及时发现超时风险，而不是事后复盘。
Pass衡量 guardrail 放行率和被拒绝原因。
Route跟踪 billing automation、billing review 与 technical handoff。
Sentiment客户情绪异常时及时报警。
06 · Roadmap

三阶段推进：先规范行为，再辅助调查，最后自主调查。

Phase 1 不是终点，而是后续自动化的安全地基。没有真实 replay、dashboard 和 guardrail，就不进入扩大切流。

Phase 1

自主检测 + 行为规范

Zendesk 转发、routing、assignment、guardrail reject / approve、dashboard 指标和真实 case replay。

Phase 2

辅助调查 + 人 approve

AI 先调查并生成 draft，人做 approve、revise 或 override；质量低于门禁时回退人工。

Phase 3

自主调查 + Agent-to-Agent

Support agent 接入研发 agent、日志 agent、数据 agent，让人转向例外处理和质量抽查。

Closing

Phase 1 要证明的不是 AI 会说话，而是 support 系统可以实时检查质量、解释决策、控制风险，并为小流量自动化打下地基。
