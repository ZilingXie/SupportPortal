Engineer AI Multi-Agent 主线实施计划

把当前仅承担 guardrail 的 Engineer AI，逐步演进为线上多 Agent 调查主链路，同时保留现有 guardrail 作为工程师批准后的最终安全门禁。

状态：实施计划 日期：2026-06-11 格式：HTML 语言：中文

给执行型 agent 的要求：实现该计划时，必须使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans，并按任务逐项执行与验证。

目标：把当前只承担 guardrail 的 Engineer AI，替换为线上 Engineer Multi-Agent 调查主链路，同时保留 guardrail 作为工程师批准后的最终安全校验。

架构：主链路由 Plan Agent、Memory Review Agent、Implement Agent、Conclude Agent 组成。工程师可以 approve 或 revise；approve 后进入 Engineer Guardrail，revise 后重新进入 Plan Agent，并带上上一轮 plan、evidence 与 revise note。

技术栈：backend/services 下的 Python 服务、backend/main.py 中的 FastAPI 路由、backend/repositories/ticket_repository.py 中的存储层、ui/engineer-ui/app.js 中的工程师前端，以及 backend/tests 下的 unittest 合约测试。

一、当前下一步

当前下一步 是先完成 任务 1：后端骨架与数据契约。这个任务故意不接入 backend/services/engineer_agent.py，不调用 LLM，不访问 repository，不改 UI，也不改变现在线上工程师工作流。它只负责建立一个可预测、纯 Python 的契约模块，供后续任务继续扩展。

三、任务 1：后端骨架与数据契约

目标：建立第一个仅后端可见的 multi-agent skeleton，为 plan、reviewed plan、task result、conclusion 定义稳定契约，同时不启用任何线上行为。

非目标：不调用 LLM、不访问 ticket_repository、不查询 Case Memory、不调用 RAG、不修改 engineer_agent.py、不增加 feature flag、也不暴露 API/UI 行为。

涉及文件：backend/services/engineer_multi_agent.py、backend/tests/test_engineer_multi_agent.py

要引入的契约

执行步骤

  1. 先创建失败测试文件 backend/tests/test_engineer_multi_agent.py，其中必须包含 test_first_step_does_not_call_llms_or_repositories，并引用 build_initial_multi_agent_plan、review_multi_agent_plan、record_multi_agent_task_result、build_multi_agent_conclusion。
  2. 运行 python3 -m unittest backend.tests.test_engineer_multi_agent -v，预期先因模块不存在而失败。
  3. 创建 backend/services/engineer_multi_agent.py，先实现 _clean_text、_clean_list、_stable_id 与两个版本常量。
  4. 补上 build_initial_multi_agent_plan 的最小实现：输出 ticket 目标、context summary、revise note、tasks 和 risk flags。
  5. 补上 review_multi_agent_plan 的最小实现：输出 scheduler shape、parallel_groups、blocked_reasons、memory_refs。
  6. 补上 record_multi_agent_task_result 的最小实现：规范化 status、evidence_refs、missing_information。

  8. 再次运行 python3 -m unittest backend.tests.test_engineer_multi_agent -v，预期全部通过。

  10. 任务 1 到此为止，不继续改 runtime 接入、Memory Review 查询、UI 或 guardrail。

四、任务 2：实现 Plan Agent

在 backend/services/engineer_multi_agent.py 中把 build_initial_multi_agent_plan 从最小版本扩展成可表达调查目标、假设、任务依赖、blocker 和 skill 驱动 task 展开的版本。先写失败测试，再实现，再跑 python3 -m unittest backend.tests.test_engineer_multi_agent -v。

五、任务 3：实现 Memory Review Agent 与调度器

只消费 Active Retrieval Memory，不碰 inactive ledger。为 reviewed plan 增加顺序、并行、blocked 三类调度语义，并在必要时扩展 backend/repositories/ticket_repository.py 的 active memory 查询接口。

六、任务 4：实现证据任务执行层

让 Implement Agent 按 reviewed plan 顺序或并行组执行 allowlisted evidence tasks。第一版保持同步和确定性，避免过早引入异步复杂度。

七、任务 5：实现 Conclude Agent

Conclude Agent 汇总证据任务结果，输出给工程师看的 conclusion，包括 confidence、root_cause_status、evidence_refs、risk_flags、missing_information 和可选的 customer_safe_draft。

八、任务 6：接入 Engineer Runtime

在 backend/services/engineer_agent.py 与 backend/main.py 中加入 feature flag、approve / revise 生命周期与 guardrail 保留路径。approve 后必须仍然经过现有 guardrail。

九、任务 7：更新 Engineer UI

在 ui/engineer-ui/app.js 中展示 multi-agent conclusion，把 revise 输入明确为“告诉 Sid 下一步要做什么，或者哪里做错了”。对应更新 backend/tests/test_engineer_ui_contract.py。

十、任务 8：回放与 Guardrail 回归测试

新增固定 fixture 的 replay tests，覆盖 plan -> review -> implement -> conclude 的可重复性；同时补 guardrail regression tests，确保已批准草稿在证据不足、内部泄露或错误 root cause 时仍 fail closed。
