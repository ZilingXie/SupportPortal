# SupportPortal POC 汇报版（2页）

## 第 1 页：结论与价值

### 1. 项目目标
在单机环境验证技术支持系统的端到端可行性，覆盖：
1. 客户端提问与工单创建
2. AI/RAG 自动处理
3. 工程师托管/接管协同
4. 管理端全局追踪

### 2. 当前结论
- 结论：**POC 部分通过，建议进入下一阶段**
- 已验证：架构可运行、三端可访问、工单链路闭环可达成
- 待验证：性能压测、稳定性基线、线上级监控告警

### 3. 已落地架构
`Nginx + API + WS Gateway + Worker + Redis + PostgreSQL`

关键价值：
1. API 快速返回，耗时 AI 查询改为异步处理
2. WebSocket 推送与 API 解耦，便于后续扩展
3. 工单/事件持久化，支持审计与追踪

### 4. 业务能力覆盖
1. 客户问题 -> 工单化管理
2. 情感识别 -> 高风险人工介入
3. Agora 相关性判断 -> 非范围拒答
4. RAG 命中自动回复，未命中升级工程师
5. 工程师托管/接管两模式可切换

## 第 2 页：进展、风险、下一步

### 5. 当前进展（截至 2026-03-08）
| 项目 | 状态 | 说明 |
|---|---|---|
| 三端页面可访问 | 已完成 | `/client/` `/engineer/` `/dashboard/` |
| 单机部署链路 | 已完成 | 本地 Podman、EC2 Docker 双路径 |
| 异步处理链路 | 已完成 | Redis 队列 + Worker |
| 实时事件推送 | 已完成 | WS Gateway 独立服务 |
| 工单持久化 | 已完成 | PostgreSQL |
| 性能压测 | 未完成 | 下一阶段重点 |
| 监控告警体系 | 未完成 | 下一阶段重点 |

### 6. 主要风险
| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 高并发下队列积压 | 响应延迟上升 | 增加 worker 并发 + 队列监控 |
| 数据库连接压力 | 请求抖动/超时 | 引入连接池/PgBouncer |
| 构建网络抖动 | 交付效率下降 | 构建重试 + 镜像缓存 |

### 7. 下一阶段（2-4 周）
1. 完成压测并建立 SLA 基线（API/WS/Worker/DB）
2. 补齐监控告警（队列长度、推送延迟、慢查询）
3. 完成 EC2 + 域名 `support.stellarix.space` 联调
4. 输出上线清单（回滚、备份、证书、发布流程）

### 8. 评审建议
- 建议进入下一阶段（稳定性与容量验证）。
- 暂不建议直接生产上线，需先完成压测与可观测性建设。
